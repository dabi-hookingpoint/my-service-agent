# my-service-agent — 후킹포인트 문의 서비스 에이전트

## 서비스 소개

영화·드라마 제작사 "후킹포인트"에 들어오는 외부 문의(제작 라인업, IP 개발, 편집 의뢰, 후반작업/VFX 협업)에
1차로 응답하는 에이전트 설계다. 별도 프로젝트인 `pd-rag-chatbot`이 "공개 자료를 검색해 출처와 함께 답하는"
챗봇이었다면, 이 저장소는 그 위에 **실제 상태를 조회하고 문의를 접수하는 도구 호출**까지 하는 에이전트를
설계·검증한다. 이번 과제는 구현이 아니라 설계가 범위이므로, `my-agent/`의 코드는 도구 계약이 실제로
작동하는지 확인하기 위한 최소한의 검증용이다.

## 설계 결정 요약

**도구를 4개(읽기 3 + 쓰기 1)로만 둔 이유.** 후킹포인트에 들어오는 문의는 실제로 "찾아본다"(정책 검색,
라인업 확인, 권한 상태 확인)와 "접수한다"(문의 남기기) 두 종류의 동작으로 전부 설명된다. 도구를 더 쪼갤
수도 있었지만(예: 카테고리별로 별도 검색 도구), 그러면 경계가 겹치는 도구가 늘어나 "이 질문엔 어느 도구를
불러야 하나"가 오히려 헷갈릴 것 같아 4개로 묶었다.

**권한을 읽기/쓰기로 나눈 기준.** 상태를 바꾸지 않는 조회는 되돌릴 수 있으니 승인 없이 바로 호출해도
위험이 없다. 반면 `submit_inquiry`는 담당자에게 실제로 전달되는 기록을 남기는 행동이라, 사용자가 내용을
확정하기 전에 잘못 호출되면 담당자 시간을 낭비시킨다. 그래서 쓰기 도구 하나에만 "실행 전 사용자 확인"을
걸었다.

**실패 뒤 행동을 그렇게 정한 근거.** 도구 오류(`TOOL_ERROR`)는 일시적일 수 있어 1회 재시도 후 안내로
정했고, 인자 누락(`MISSING_ARG`)은 재시도로 해결되는 문제가 아니라서 곧바로 되묻기로 정했다. 승인/정책
예외처럼 애초에 이 에이전트의 권한 밖인 것(`ESCALATION`)은 재시도하지 않고 바로 담당자 이관 문구를
붙이도록 했다 — 재시도해봐야 같은 결과가 나올 게 뻔한데 사용자를 기다리게 할 이유가 없기 때문이다.

## 실행하지 않은 것과 이유

- **실제 LLM 툴콜링 루프**: 이번 과제 범위는 설계 문서 작성이라, 어떤 도구를 호출할지는 매 트레이스에서
  에이전트 역할(Claude)이 직접 판단해 실행했다. 실제 모델이 이 설계대로 도구를 고르는지는 다음 단계에서
  Gemini/Claude API로 실제 툴콜링 루프를 붙여 측정할 지점이다.
- **`check_ip_access`/`submit_inquiry`의 실제 담당자 승인 흐름**: 지금은 목 데이터(`ip_access_grants.json`)와
  로컬 로그 파일(`inquiries.log.json`)로만 동작한다. 실제 서비스라면 담당자가 승인 상태를 바꾸는 별도
  인터페이스가 있어야 하는데, 이번 범위 밖이다.
- **동시성/중복 접수 처리**: 같은 사람이 같은 문의를 여러 번 접수했을 때 병합하거나 걸러내는 로직은 만들지
  않았다. 실제 운영 전 다음으로 측정해야 할 지점이다.
- **인증**: `contact_email`을 사용자가 자기 것이라고 주장하면 그대로 믿는다. 이메일 소유 확인(인증 메일
  발송 등)은 이번 설계에 넣지 않았다 — 1차 문의 접수 단계에서는 과설계라고 판단했지만, IP 열람처럼 민감한
  기능이 늘어나면 다음에 측정해야 할 지점이다.

## 저장소 구조

```
my-service-agent/
├── README.md              (이 문서)
├── design-packet.md        (설계 패킷 7항목)
└── my-agent/
    ├── tool-definition.md  (실제 구현된 4개 도구 문서 + 실행 예시)
    ├── tools.py             (도구 실제 구현)
    ├── data/                (검증용 데이터 — chunks.json은 pd-rag-chatbot에서 복사, 나머지는 목데이터)
    └── traces/              (trace-01~05.txt — tools.py를 실제로 호출해 남긴 실행 기록)
```
